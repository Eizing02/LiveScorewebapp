# ลำดับลีกในโปรแกรมบอล

ดำเนินงานวันที่ 28 ตุลาคม 2026 เวลาไทย หลังผู้ใช้อนุมัติแผนด้วย “ลงมือทำ” ในโปรเจกต์ `D:\Football Prediction AI`

## กติกาที่ใช้

เป็นลำดับเพื่อการใช้งานตามความต้องการของเจ้าของโปรเจกต์ ไม่ใช่อันดับความแข็งแกร่งหรือคะแนนจากโมเดล

| กลุ่ม | ลำดับภายในกลุ่ม |
|---|---|
| ลีกหลักยุโรป | พรีเมียร์ลีก → ลาลีกา → เซเรียอาอิตาลี → บุนเดสลีกา → ลีกเอิงฝรั่งเศส |
| ถ้วยสโมสร UEFA | Champions League → Europa League → Conference League |
| Championship | Championship อังกฤษ |
| ถ้วยหลักในประเทศ | FA Cup → League Cup → Copa del Rey → DFB Pokal → Coppa Italia → Coupe de France |
| ลีกสูงสุดอื่นในยุโรปที่กำหนด | เนเธอร์แลนด์ → โปรตุเกส → ตุรกี → เบลเยียม → สกอตแลนด์ |
| ลีกหลักเอเชียและอเมริกาที่กำหนด | ไทย → ญี่ปุ่น → เกาหลีใต้ → บราซิล → อาร์เจนตินา → MLS → ซาอุดีอาระเบีย |
| ลีกระดับรองที่กำหนด | Segunda División → Serie B → 2. Bundesliga → Ligue 2 → League One → League Two → National League |
| รายการที่ยังไม่ได้กำหนด | ประเทศ → ชื่อรายการ → Provider League ID |

ภายในแต่ละลีกเรียง kickoff จากก่อนถึงหลัง และใช้ fixture ID ตัดสินเมื่อเวลาเท่ากัน โดยจัดรอบวันไทย 06:00–ก่อน 06:00 วันถัดไปตามเดิม รายการที่ไม่มีคู่ในรอบหรือไม่ตรงตัวกรองจะไม่ถูกเพิ่มเป็นกลุ่มว่าง

ใช้ **Provider League ID** กำหนดลำดับ เช่น Serie A อิตาลี ID 135 กับ Serie A บราซิล ID 71 อยู่คนละกลุ่ม ชื่อเหมือนกันไม่ทำให้ได้อันดับเดียวกัน ลีกที่กดติดตามยังใช้ลำดับเดิม การค้นหาและกรองประเทศ/สถานะไม่เปลี่ยนลำดับความสำคัญ

## สิ่งที่แก้

- สร้าง `packages/football/competition-order.ts` เป็นจุดกำหนดนโยบายเดียว มี 34 competition IDs ใน 7 กลุ่ม
- แก้ `apps/api/program.ts` ให้เรียง metadata รายการแข่งขันและ fixture ด้วยนโยบายเดียวกัน **ก่อน LIMIT/OFFSET** จึงไม่เกิดกรณีลีกใหญ่ถูกดันไปหน้าหลังเพราะลีกเล็กเตะเช้ากว่า
- กลุ่มที่ไม่มีอันดับใช้ชื่อประเทศ/รายการอย่างคงที่ หากชื่อของรายการเดียวกันแตกต่างกันระหว่าง observation ใช้ค่ากลุ่มที่คงที่ในการเรียง เพื่อให้ลีกเดียวกันอยู่ต่อเนื่องกัน
- แก้ `apps/web/src/ProviderPreview.tsx` ยกเลิกลำดับเฉพาะหน้าจอ เมนูซ้ายและ dropdown ใช้ metadata ที่ API เรียงแล้ว ส่วนกลุ่มคู่รักษาลำดับของ fixture ที่ได้รับ
- เพิ่ม `tests/program-order.test.ts` และขยาย `tests/ui/one-page.spec.ts` ตรวจลำดับจริงผ่าน D1/API และหน้าจอ
- ปรับ `PRODUCT.md` และ `README.md` ให้บันทึกพฤติกรรมใหม่

ไม่ต้องเปลี่ยน schema หรือนำข้อมูลเข้าใหม่ การเปลี่ยนนี้เป็นการเรียงตอนอ่าน ไม่แก้ fixture observations, scores, identity mapping, จำนวนคู่, training dataset หรือเกณฑ์คัดโมเดล

## การตรวจ

การทดสอบเฉพาะส่วนสร้างข้อมูลแยกจากแคชจริง โดยมีคู่ลีกเล็กที่เตะก่อนมากกว่า 25 คู่ และลีกใหญ่ที่เตะภายหลัง ตรวจว่าลีกใหญ่ยังอยู่หน้าแรก ทุกหน้ารวมกันไม่มีคู่หาย/ซ้ำ ลำดับใน metadata ตรงกับกลุ่ม fixture และเวลาเรียงถูกต้องภายในลีก นอกจากนี้ตรวจชื่อซ้ำต่าง ID, fallback, country/league/following filters และไม่สร้าง prediction ใหม่

Browser test ใช้ catalogue จริงที่บันทึกไว้ ตรวจลำดับเมนู กลุ่มคู่ และ dropdown บนคอมกับมือถือ มีภาพ `reports/league-order/desktop.png` และ `mobile.png` ผลคำสั่งและจำนวนข้อมูลขณะตรวจอยู่ใน `reports/league-order/verification.json`

## ปรับลำดับภายหลัง

แก้เฉพาะรายการ IDs ใน `PROGRAM_COMPETITION_GROUPS` ที่ `packages/football/competition-order.ts` แล้วรัน `npm test`, `npm run lint`, `npm run build` และ `npm run test:ui` ตามขั้นตอนตรวจของโปรเจกต์ อย่าสร้าง priority list เพิ่มใน frontend อีกที่หนึ่ง และอย่าอนุมาน ID จากชื่อที่ซ้ำกัน

รายการที่กำหนดไว้แต่ยังไม่มีข้อมูลจะแสดงเมื่อมี fixture ที่ตรง ID เข้ามา การตั้งค่าอันดับไม่ยืนยันว่าบัญชี API เข้าถึงรายการหรือฤดูกาลนั้นได้ รอบนี้ไม่มีคำขอ API-Football v3 เพิ่ม ไม่มีการ deploy, remote D1 write หรือ model promotion และไม่แก้โปรเจกต์เดิม `D:\Live score Project`
